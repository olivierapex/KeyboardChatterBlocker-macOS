Keyboard Chatter Blocker for macOS
----------------------------------

A lightweight macOS app that blocks mechanical keyboard chatter, where a single key press is typed twice or more. It drops a key press when it comes too soon after the previous press of the same key. You can set the threshold globally and per key.

This app was inspired by, and ports the blocking logic of, [FreneticLLC/KeyboardChatterBlocker](https://github.com/FreneticLLC/KeyboardChatterBlocker), the Windows tool by Alex "mcmonkey" Goodwin and Frenetic LLC.

## Requirements

- macOS 15 or newer (built and tested on macOS 27)
- Xcode or the Command Line Tools (`xcode-select --install`)

## Install

```sh
./install.sh
```

This builds the app, copies it to `/Applications`, and installs a launch agent (`~/Library/LaunchAgents/local.KeyboardChatterBlocker.plist`). The launch agent starts the blocker in the background at every login, and launchd restarts it within about 10 seconds if it ever stops. The blocker has no icon or window and uses about 3 MB of memory.

On the first run, macOS asks you to grant **Accessibility** permission (System Settings > Privacy & Security > Accessibility). Turn on **KeyboardChatterBlocker**. Blocking starts as soon as you do; the app doesn't need a restart.

There's no Apple Developer ID here: the app is built on your Mac and ad-hoc signed, so Gatekeeper never quarantines it. Accessibility permission is tied to the exact binary, so after a rebuild, remove the app from the Accessibility list with `-` and add it again.

To only build the app without installing it, run `./build.sh`. The result is in `build/`.

## Uninstall

```sh
launchctl bootout gui/$(id -u)/local.KeyboardChatterBlocker
rm ~/Library/LaunchAgents/local.KeyboardChatterBlocker.plist
rm -rf /Applications/KeyboardChatterBlocker.app ~/Library/Application\ Support/KeyboardChatterBlocker
```

## Usage

Blocking runs in the background with no icon. To change settings, open **KeyboardChatterBlocker** from Applications or Spotlight. The window has three tabs:

- **General**: the **Enabled** switch, the global chatter threshold, the options described under Config File, and whether the background blocker is running.
- **Configure Keys**: press **Add Key…** and then the key to add it, then edit its threshold in the table.
- **Chatter Log**: every blocked press, with the key and how many milliseconds after the previous press it came. **Configure** adds that key to the per-key list.

The settings window is a separate process from the background blocker, and it quits when you close the window. The two stay in sync through the config file and `chatter_log.txt` in the same folder. The log is cleared each time the background blocker starts.

### Tuning

1. Set the global threshold to `0`.
2. Add each key that chatters under **Configure Keys** with a threshold of `300`.
3. Type normally and watch the **Chatter Log**.
4. Set each key's threshold a bit above the highest delay logged for it (for example `100` if you saw `52, 73, 64`). The threshold should be higher than the chatter, but low enough that it never blocks normal fast typing.

## Config File

The config file is at `~/Library/Application Support/KeyboardChatterBlocker/config.txt`, with one `name: value` setting per line:

- `is_enabled`: `true` or `false`.
- `global_chatter`: default threshold in ms for every key.
- `minimum_chatter_time`: repeats faster than this many ms are let through (a workaround for buggy inputs; `0` disables it).
- `measure_from`: `Press` or `Release`, whether to measure the delay from the last press or the last release of the key.
- `other_key_resets_timeout`: `true` to reset a key's timeout when another key is pressed in between.
- `exclude_injected`: `true` to ignore key events generated by software instead of a keyboard.
- `key.<KEY>`: threshold in ms for one key, for example `key.H: 150`.

Key names follow macOS key positions on a US layout (`A`, `1`, `Space`, `Return`, `Delete`, `LeftBracket`, `F5`, `Keypad3`, …). Any other key can be written by its virtual key code, for example `key.keycode_105`. If a line can't be read, the app ignores it and lists it on the General tab.

## Limitations

- Modifier keys (Shift, Control, Option, Command, Caps Lock, fn) and media keys are never blocked.
- While a password field has focus, macOS turns on Secure Event Input and hides keystrokes from the app, so chatter isn't blocked there.
- Settings apply to all connected keyboards. macOS doesn't report which keyboard sent a key event.
